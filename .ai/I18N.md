# I18N.md — Internationalization Setup & Status

> Updated: 2026-05-18

## 🌍 Current Status (Phase 3 Complete)
The project now uses a dynamic `I18n` class (`js/i18n.js`) for client-side localization without page reloads.
Supported locales: English (`en`), Russian (`ru`), Ukrainian (`uk`).

## 🔄 Lifecycle Adjustments
- `i18n.applyTranslations()` is strictly coupled to the `ComponentLoader` lifecycle.
- It listens for the `componentsReady` event to guarantee that all dynamic HTML (injected via `data-component`) is present in the DOM before translating.
- Switching language triggers a re-render of static translations in the current DOM state and updates `localStorage`.

## 🛠️ Fixed Translation Issues
- Extracted hardcoded UI strings from `navbar.html`, `sidebar.html`, `services.html`, `pricing.html`, `counters.html` and `index.html` banner.
- Mapped JSON configuration properties (e.g., `label` in `navigation.json`) directly to locale keys. Example: `"label": "navigation.portfolio"`.
- Template injection now successfully wraps these mapped variables in `<span data-i18n="{{label}}">{{label}}</span>`.

## 🎨 Rendering Parity Fixes
- Added standard emoji flags to the navbar UI (🇬🇧 EN, 🇷🇺 RU, 🇺🇦 UK) ensuring consistent multi-platform rendering without requiring external SVG assets.
- Prevented un-translated text flashes by resolving race conditions in the init sequence.

## ⚠️ Remaining Untranslated Blocks
- **`onepage.html`**: Still retains the monolithic structure. It requires either manual `data-i18n` wrapping for its entire 2,000+ line structure or a full component migration.
- **Dynamic Content within Data Files**: Blog post bodies (`blog-post.json`) and portfolio descriptions (`project-single.json`) currently contain single-language mock data. To support full data translation, these JSON schemas might need to be structured per-locale (e.g., `description_en`, `description_ru`) or moved to locale-specific data directories.
